# Standardized ingestion templates

`plantillas_estandarizadas.json` (generated by the Phase 0 interview; start from `plantillas_estandarizadas.example.json`) defines, for each fixed ingestion type, everything that the Shortcut does NOT need to ask. Edit it by hand when something changes (provider, paying account...). The workflow code is never touched for that.

## Versioning (same as `categorias` in Supabase)

Each ingestion type is an **array** of versions with `fecha_inicio` / `fecha_fin`. The current version is resolved as:

```
fecha_inicio <= fecha_operacion AND (fecha_fin IS NULL OR fecha_operacion <= fecha_fin)
```

If you change provider or paying account: **do not edit the existing version**. Close it by setting `fecha_fin` and append a new version. History keeps resolving with the template that was valid at each date.

## What the JSON does NOT carry (and why)

- **`tipo`**: derived from `categorias.tipo` of the row's `codigo_categoria`. Invariant of the database.
- **`medio_pago`**: set by the `trg_set_medio_pago` trigger from the account used.
- **A fixed `id_categoria`**: never. Only the slug `codigo_categoria` is stored; the real id is resolved at insert time by slug + validity date (categories are SCD2: same code, different id per date range).

## Field convention

| Field | Meaning |
|---|---|
| `id_cuenta` | Fixed id if the account never changes for that type. **`null`** = the Shortcut sends the account **name** as text and the script resolves it against `cuentas.nombre_cuenta`. |
| `codigo_categoria` | Category slug; real id resolved in Supabase by valid date. |
| `id_etiqueta` | Labels are not versioned, so the id goes directly. |
| `importe_fijo` | Number if the amount never changes. **`null`** = the Shortcut provides it (variable amount). |
| `signo` | Present when `importe_fijo` is `null`. The Shortcut always sends a positive amount; `signo` (`1`/`-1`) says whether the template is money out or money in. |
| `comentario_fijo` | Literal fixed comment text. |
| `comentario_fuente` | Path to data already in Supabase (currently only `categorias.glosa`). |
| `comentario_desde_shortcut` | `true` = the user types the comment in the Shortcut. |

If a field (`id_cuenta`, `importe_fijo`) is `null` and there is no `comentario_*`, the Shortcut asks for it. Nothing is asked that can be resolved another way ("minimum data possible").

## Multi-row templates: `filas`

Templates with a `filas` array create several linked rows in one atomic insert. Each row has a `rol`, a `signo` and an `id_cuenta`:
- `id_cuenta: "CU..."`: fixed account.
- `id_cuenta: null`: the account sent by the Shortcut as `cuenta`.
- `id_cuenta: null` + `"cuenta_payload": "cuenta_destino"`: the account sent as `cuenta_destino`.

Used by **savings** (`ahorro_aporte`, `ahorro_retiro`: transfer between a spending account and a savings account) and **credit card payment** (`pago_tarjeta`: negative row on the paying account, positive row on the card, so the card's debt goes down and works with any number of cards).
